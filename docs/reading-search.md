# 読み候補の探索 — 2026-10-20

SudachiDict **Full 20261015** / SudachiPy **0.7.0** を情報源とする、選択表記の読み探索を実装した。一般辞書の読みを作者の意図として自動確定せず、観測方法を選び、得られた根拠と基準の辞書順を比較し、作者が採用する。


## 操作

1. 歌詞AまたはBで、タグを含まない1行内の表記を選ぶ（最大64 UTF-16単位）。右の「読み候補を探す」、または「編集 → 読み候補を探す」を開く。
2. 初期探索は自動で始まる。「選択表記の目標」にモーラ数を入れて「条件を変えて探索」で比較し直せる。行全体の目標や英語シラブル数とは別の条件。
3. 「探索順／辞書順」を切り替え、候補のモーラ数、目標との差、根拠を確認する。複数候補がある場合も未選択で表示する。
4. 必要なら「追加で調べる」から未観測の方法を選ぶ。「探索の経過」には、方法を選んだ理由、新しい候補・根拠、終了理由、残った方法を表示する。
5. 候補を選択し「この読みを採用」で反映する。「保留して閉じる」「現在の読みを維持」では何も変更しない。「手動で入力」から自由に読みを設定できる。

たとえば「明日」には「あす」2 mora、「あした」3 mora、「みょうにち」4 mora がある。目標を3にすると「あした」を先に提示するが、意味や作者の意図が正しいことを示す順位ではない。「届かない」の「届」のような場合は、形態素「届か＝トドカ」の選択外の「か」を照合して「とど」を派生候補として得る。漢字の字数を使って読みを切り分けることはしない。

## 選択範囲をまとめて設定

複数行や全文を選択し、右の「選択範囲の読みを一括設定」、または「編集 → 選択範囲の読みを一括設定」を開く。本文で `Ctrl+A` を使うと全文を選べる。

Sudachiの形態素解析で選択範囲を語に分け、未設定の漢字を含む語ごとに既存の適応探索を実行する。探索順1位の候補を仮選択した一覧を表示し、作者は各語の候補を変更したり、手入力・保留を選んだりしてから「選んだ読みを一括適用」で決定する。「すべて保留」「候補の先頭をまとめて選ぶ」も用意した。仮選択・探索中・閉じる操作では歌詞を変更しない。


既存のルビ・音節指定は、選択範囲に一部分だけ含まれている場合も保持する。タグと閉じていないタグ内、かなだけの語、英語は対象外。通常は形態素単位（例「届かない」の「届か」）の範囲になり、選択が「届」だけならその範囲内に限って候補を調べる。字数から漢字の読みを分割して補うことはしない。

適用直前に全語の文書・範囲・読み・既存注釈との非重複を確認し、1つの編集操作として反映する。前後の編集と履歴を分離するため、1回のUndoで今回の全語を戻せる。A/Bの操作対象外の歌詞には適用しない。個人辞書への一括登録は任意のチェックで指定し、複数の採用記録を1回の保存で統合する。Undoで個人辞書の記録は削除しない。

上限は選択範囲8,192 UTF-16単位、128語、探索全体60秒。途中で中止・再探索できる。語の区切りや候補を取得できなかった範囲は未確認として表示し、全文に設定できたと装わない。個人辞書・本文・IME状態が変わった場合は古い結果を採用せず、辞書版が変わった場合も全体を失効させる。

## 観測と選択

SIDUS参照資料の「作用 → 観測 → 比較 → 次の作用選択」を、有限の辞書観測に適用した最初の実装。観測計画は固定の全実行でも、辞書候補の並べ替えだけでもない。現在の候補集合・選択範囲の被覆・作者指定との衝突・新しい根拠の有無によって次の観測を選ぶ。

| 観測 | 調べること |
|---|---|
| 表記の辞書照会 | 同じ表記の見出し・読み・品詞・出典ID。辞書の返却順を比較基準として固定 |
| 周囲の文脈 C | 長い形態素単位で選択範囲の読みを確認 |
| 作者指定 | この歌詞の別箇所と、明示登録した個人辞書の読み・衝突を確認 |
| 周囲の文脈 A/B | Cで範囲を覆えない場合などに、細かい／中間の単位で再観測 |
| 別の用例 | 曖昧さや作者指定の衝突があるとき、文書内の同じ表記の別文脈を確認（最大3用例） |
| 文脈窓の変更 | 近い文脈だけ、または選択表記だけで、読みが変わるか比較 |

初期の表記照会・文脈C・作者指定を観測した後、未被覆ならA/B、曖昧なら別用例などへ進む。候補が1つで文脈の被覆も得られた場合、目標一致候補を文脈でも観測できた場合、追加観測の収穫がなくなった場合などは停止する。取得失敗と候補なしは区別する。自動探索は最大8観測・10秒、作者が選ぶ追加照会は既存結果を引き継いで1観測ずつ行う。

同じ読みに複数の根拠をまとめても、元の形態素・辞書見出し・用例・版は保持する。A/B/Cは同じ解析系なので、独立した多数決や確率には換算しない。提示順は、適用可能性、目標モーラとの差、この文書の作者指定、個人辞書、文脈の観測、辞書見出し、元の辞書順の順で比較する。目標と合わない候補も削除しない。

辞書順は最初の表記照会に含まれた候補だけの比較基準。文脈や作者指定で追加された候補をそこへ混ぜない。各候補の元の順位と探索による順位変化も表示する。実験結果を見ながら、この方策を将来改善できる構成にしている。

## 確定・保存・境界

- 探索中の候補は `inferred_candidate` のまま保持し、歌詞のJSONや確定音数へ書き込まない。明示的な採用時だけ、従来形式の `rubyReading` / `author_ruby` として1回のUndo対象にする。
- 既存の読みは選択範囲と完全一致するときだけ「現在の読み」と表示する。読みの一部だけを選んだ変更は、選択範囲外の注釈を損なうため拒否し、全体選択を案内する。
- 原文は正規化せず、JavaScriptとPython間の範囲はUTF-16単位へ揃える。非BMP文字の前後でも対象表記を再照合する。正規化された見出しの表記と元の表記が異なる結果を、完全一致とは扱わない。
- 本文変更、IME変換状態、ペイン切替、探索の閉鎖、個人辞書の変更で古い結果を失効させる。採用直前にも文書・範囲・タグ・読みを確認する。取消済みの遅い応答は適用しない。
- 辞書が停止・未導入でも編集機能を保持し、個人辞書の候補や手動入力へ移れる。候補が得られない場合に読みを捏造しない。

## 個人読み辞書

候補採用時の「採用した読みを個人辞書に登録」、または手動入力時の登録チェックを明示した場合だけ記録する。既存サンプル、文書の取り込み、候補を眺める操作から自動学習しない。保存内容は表記・読み・採用日時・前後文脈・文書ID・由来・辞書版など。複数の読みを残せる。

「編集 → 個人読み辞書」で検索、個別削除、`.lyrics-readings.json` の書き出し・統合取り込みができる。歌詞のUndoは読みの注釈を戻すが、採用したという辞書記録は残すため、不要ならここで削除する。歌詞のネイティブ形式は変更しておらず、辞書のバックアップは別に行う。

保存先は同じブラウザーorigin内の独立したIndexedDB。破損・未来版・衝突したIDを黙って上書きせず、元データの書き出し、明示した退避付き初期化を用意する。取り込み失敗は既存辞書を変更しない。歌詞に読みを適用できても辞書保存に失敗した場合は、その違いを通知する。

## 実行と検証の境界

`npm run setup:readings` → `npm run dev` で開発起動。本番は `npm run build` → `npm start`。Python専用環境、固定版、辞書のサイズ・SHA-256・ライセンスは [ローカル解析サービス](../backend/README.md) と [出典記録](../backend/provenance.json) にある。外部へ歌詞を送信せず、初回の辞書導入後は外部ネットワーク不要。ただしブラウザーだけでFull辞書を実行する構成ではなく、ローカルPythonプロセスが必要。

単体テストは、観測分岐、基準順の保持、根拠の統合、UTF-16、OOV、かな照合、終了・取消・再開・失効を検証する。Pythonテストは実Full辞書とHTTP APIを使う。Chrome E2Eの正常系も実Full辞書を使い、採用・Undo・A/B・保存・個人辞書・既存注釈の範囲・遅延応答・破損復旧を通して確認する。

作者の意図に対する正解率や、固定辞書順に対するSIDUS方策の優位性を実証したものではない。現在の読みを正解ラベルとして順位付けへ流用することも避けている。実歌詞での評価、意味・歌唱表現の評価、OS IMEへの「表記→読み→再変換」の双方向探索、同じモデルのN-best候補生成、作者の確認なしでの全文自動確定は今後の範囲。
