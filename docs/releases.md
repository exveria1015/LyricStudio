# リリースの準備と確認

この文書は保守者向けの手順です。現在の変更は [CHANGELOG](../CHANGELOG.md) のUnreleasedに記録しています。

1. 公開予定のGit履歴に秘密情報、個人データ、非公開資料がないことを確認します。現在のファイルから削除しただけでは過去の履歴から消えません。
2. クリーンなcloneでREADMEのセットアップを実行し、lint・単体テスト・Pythonテスト・ビルド・E2Eを確認します。WindowsとLinuxのCI結果を確認します。
3. 読みの編集、Undo、保存・再読込、A/B切替を確認し、実機IMEなどの未確認項目をリリースノートへ明記します。
4. パッケージ版、辞書版、必要環境、既知の制限をREADMEと変更履歴に反映します。
5. ビルド済みファイルを添付する場合は、同梱依存物の著作権表示とライセンス本文を含めます。個人の保存データや仮想環境は配布しません。
6. 対象コミットを確認してバージョンタグとGitHub Releaseを作成します。初期版はPre-releaseとして扱います。作成操作は手動で行います。
7. 公開後、未ログイン状態で説明・リンク・ソース取得を確認します。

## リリースノートの例

```text
LyricStudio vX.Y.Z（プレビュー）

変更内容:
- ...

導入:
- READMEの手順を参照
- Node.js / Pythonの必要版、辞書の導入が必要

確認した環境・テスト:
- ...

既知の制限・未確認事項:
- ...

データの移行:
- 必要な場合は、変更前にワークスペースと個人辞書を書き出す
```
