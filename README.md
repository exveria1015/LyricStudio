# LyricStudio

表記・歌う読み・音数・楽曲構成をひとつの画面で扱う、ローカルで動作する作詞エディターです。日本語のモーラと英語のシラブルを別々に集計し、読みが不明な箇所は未確定として表示します。

現在は初期開発版です。作成した歌詞は、ブラウザーの自動保存に加えてファイルへ書き出して保管してください。

## 主な機能

- 表記を保ったまま歌う読みを設定・修正し、Undo / Redoで戻せます。
- 日本語モーラ、英語シラブル、Verse / Chorusなどの構成タグを確認できます。
- 原詞と訳詞をA/Bで編集し、セクションや行を対応させて比較できます。
- SudachiDict Fullによる読み候補探索、選択範囲への一括設定、個人読み辞書を利用できます。候補は作者が選んで採用します。
- 自動保存、歌詞・ワークスペースのJSON保存、テキスト入出力に対応します。

## 必要な環境

| 項目 | 条件 |
|---|---|
| OS | Windows（PowerShell）またはLinux。macOSは未確認 |
| Node.js | 24系を推奨。対応範囲は22.13以上の22系・24系・26系以上。CIは24系 |
| Python | 読み探索を使う場合は3.10以上 |
| ブラウザー | Chromium系を自動テスト対象としています。Web Locks・IndexedDBが必要です |
| ネットワーク | 初回のパッケージ・辞書取得時に必要。導入後の通常の解析はローカルで完結 |

Node.jsとPythonは各公式配布元から導入してください。WindowsではPythonランチャーの `py -3`、またはPATH上の `python` を使用します。Bash、WSL、仮想環境の手動activateは不要です。

`setup:readings` はプロジェクト内の `.venv-sudachi` を作成し、その中のpipを26.3へ更新してから読み解析用の依存を導入します。既存の環境も同じコマンドで更新できます。

## 導入

```sh
git clone https://github.com/exveria1015/LyricStudio.git
cd LyricStudio
npm ci
npm run setup:readings
npm run dev
```

Windows PowerShellでも同じコマンドを使います。ブラウザーで **http://127.0.0.1:5173** を開いてください。終了は起動した端末で `Ctrl+C` です。

初回は読みをあらかじめ指定したサンプル歌詞を表示します。読み探索を使わない場合は `setup:readings` を省略でき、本文編集・手動の読み設定・英語シラブル計数を利用できます。

`setup:readings` はプロジェクト内の `.venv-sudachi` にSudachiPy 0.7.0とSudachiDict Full 20261015を導入します。辞書だけでダウンロード約131 MiB、展開後約315 MiBを使用します。インストール用の一時ファイルにも空き容量が必要です。

PowerShellで「スクリプトの実行が無効」と表示された場合は、`npm` を `npm.cmd`、`npx` を `npx.cmd` として実行してください。Pythonを明示的に指定する場合は、実行ファイルへのパスを設定してからセットアップします。

```powershell
$env:LYRICS_PYTHON = 'C:\path\to\Python\python.exe'
npm.cmd run setup:readings
```

`LYRICS_PYTHON` は新しい仮想環境を作る際に使用します。既存の `.venv-sudachi` は再利用します。別OSで作った仮想環境はコピーせず、各OSでセットアップしてください。

## 基本操作

1. 歌詞を入力するか、上部の「開く」からテキスト・保存済みJSONを取り込みます。
2. 表記を選択し、右側で読みを入力するか「読み候補を探す」を使います。`Alt+R` でも読み欄へ移動できます。
3. 複数行の読みは「選択範囲の読みを一括設定」で確認し、選んだ候補をまとめて適用できます。
4. `[` / `［` で構成タグの候補を表示します。矢印キーで選び、Enter / Tabで確定します。
5. 「保存」または `Ctrl+S` で、読みを保持した歌詞ファイルを書き出します。

「A/B比較」で別の歌詞を並べられます。`Alt+1` / `Alt+2` で操作対象を切り替え、左右・上下の分割を選べます。タイトル・読み設定・通常の保存は選択中の歌詞が対象です。

左上のロゴまたはメニューバーから各機能を開けます。`Alt+F10` でメニューへ移動し、矢印キーで操作できます。個人読み辞書は「編集 → 個人読み辞書」で確認・書き出し・取り込みができます。

詳細は [A/B・セクション比較](docs/comparison.md)、[読み探索ガイド](docs/reading-search.md) を参照してください。[サンプル歌詞](examples/sample-lyrics.txt)はプレーンテキストの例で、読み注釈は含みません。

## 保存とバックアップ

| 操作 | 保存内容 |
|---|---|
| 自動保存 | このブラウザーのIndexedDB。別の端末やブラウザーへは同期しません |
| 保存 / Ctrl+S | 操作中の歌詞と読みを `.lyrics.json` に保存 |
| A/Bをまとめて保存 / Ctrl+Shift+S | 両歌詞・比較設定・分割位置を `.lyrics-workspace.json` に保存 |
| テキスト書き出し | 原文とタグ。読み注釈は含みません |
| 個人読み辞書の書き出し | 個人辞書を別のJSONファイルに保存 |

ブラウザーのサイトデータ削除で自動保存も失われます。ワークスペースと個人辞書をそれぞれ書き出して保管してください。`127.0.0.1` と `localhost`、ポート5173と4173は保存領域が異なるため、移行するときも書き出し・取り込みを使います。Undo履歴そのものは再起動後に復元しません。

同じ保存領域を使う2つ目のタブは待機します。先のタブを閉じると最新の歌詞を読み込みます。自動退避した過去コピーを選んで復元する画面は未実装です。

起動時に保存データを読み込めない場合は「保存された元データを書き出す」でファイルに保管できます。壊れたJSONや新しい形式も、文字列を変更せずに書き出します。ブラウザーの容量が不足していても、読み込みとダウンロードが可能なら利用できます。原因を解消したら「読み込みを再試行」、新しく始める場合は「元データを退避して新しい文書で開始」を選んでください。

## ビルド済みアプリの起動

```sh
npm run setup:readings
npm run build
npm start
```

**http://127.0.0.1:4173** で画面と読み解析を提供します。`npm start` にはPythonのセットアップと事前のビルドが必要です。公開サーバーとして運用するための構成ではありません。

本番ビルドは初回読み込み後のオフライン再起動に対応します。読み探索にはローカル解析プロセスの起動が必要です。詳しくは [オフライン動作](docs/offline.md) を参照してください。`npm run preview` は静的ビルドの確認用で、読み探索には別途 `npm run dev:readings` が必要です。

## 制限・トラブルシューティング

- 読み候補は辞書・文脈からの候補であり、作者の意図や歌唱時の音数を保証しません。未確定表示を確認し、必要なら手動で指定してください。
- OSの日本語IMEによる実入力、すべてのブラウザー、スクリーンリーダーでの確認は完了していません。
- 読み探索が使えない場合は `npm run check:readings` で辞書を確認し、起動端末のエラーを調べてください。ポート8787が他のサービスに使われていないかも確認します。
- パッケージ・辞書の初回ダウンロードに失敗した場合は、接続を確認してセットアップを再実行します。
- 保存失敗が表示された場合は、サイトデータを消す前にファイルへ書き出してください。
